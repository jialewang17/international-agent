# 统一计分卡 v1（Unified Scorecard）

**状态**：规范生效（工程量表 → 可机打 + 可人工复核）  
**路径**：`eval/UNIFIED_SCORECARD_v1.md`  
**适用**：讲好中国故事 · 主动成稿（社交帖文 / 新闻通稿）；有或无用户上传资料。  
**非目标**：深度报道 feature、短视频脚本（插件位预留，材料到位后再开）。

---

## 1. 设计目标与原则

1. **两层计分，禁止神话总分**：先报 **共享层**，再报 **体裁插件**；需要汇总时用加权，但文档与 Excel **必须分列**。  
2. **内容质量 ≠ 资料关联**：两套问题分开量，避免「写得漂亮但没用资料」或「锚点堆满但体裁串味」被一个总分掩盖。  
3. **事实 > 硬约束 > 软偏好 > 系统默认**（与提示遵从 Rubric 一致）。  
4. **锚点必须专有**：增益/覆盖所用锚点不得是「仅复述 theme 就能命中」的词（规避 MF03 类假失败）。  
5. **机打 + 人打双轨**：规则分可自动；讲述/语气/受众等保留人工档，报告相关（后续人工验证用）。  
6. **体裁用插件，不另起炉灶**：帖文 / 通稿共享骨架，换插件指标。

---

## 2. 计分结构总览

```text
┌─────────────────────────────────────────────┐
│  S 共享层  Shared (0–30，6×1–5)              │
│  所有体裁、有无资料均可打（无资料时 S5/S6 有规则）│
└─────────────────────────────────────────────┘
          +
┌──────────────────┐    ┌──────────────────┐
│ P 帖文插件 (0–15) │ 或 │ N 通稿插件 (0–15) │
│ 3×1–5            │    │ 3×1–5            │
└──────────────────┘    └──────────────────┘
          =
报告：Shared /30 + Plugin /15  （可选加权总分见 §6）
```

| 层级 | 代号 | 满分 | 何时启用 |
|------|------|------|----------|
| 共享 | S1–S6 | 30 | 每条成稿必打 |
| 帖文插件 | P1–P3 | 15 | `genre=post` |
| 通稿插件 | N1–N3 | 15 | `genre=news` |

**达标线 v1（工程默认）**

| 条件 | 线 |
|------|-----|
| 共享层 | ≥ 22/30，且 **S2 越界 ≥ 4** |
| 有用户资料 | 另要求 **S1 覆盖 ≥ 3**；若设计了无资料对照，**S6 增益 ≥ 4** |

| 通稿插件 | ≥ 10/15，且 **N3 隔离 ≥ 3**（反串味） |
| 门控应拒题 | 正确拦截视为该条 **通过**（共享记满分档或单独 Gate=PASS，不与成稿分混报） |

## 3. 共享层 S1–S6（直接评「生成物 × 证据/资料」）

> 对应你提的两类问题里的 **可核验原则 + 与上传资料关联**；5W 的「可核验/受众底线」部分上收于此，体裁专属放到插件。

### S1 资料覆盖 Coverage（1–5）

- **定义**：用户资料中的 **专有锚点** 在成稿（及必要的 5W/引语）中的命中率。  
- **锚点规范（硬）**：须同时满足  
  - 来自用户资料（非模型常识套话）；  
  - **从 theme/brief 字面复述得不到**（禁止只用「焊接/火花」这类已写在标题里的词当唯一增益锚点）；  
  - 优先：人名、独特工序、独特数字、独特引语片段、列表条目。  
- **操作**：命中率 ≥60%→5；40–59%→4；25–39%→3；有命中但低→2；必用资料却 0 命中→1。  
- **无用户资料**：本维记 **N/A**，不计入共享平均（或记 3 中性，须在表头注明口径）；不得用本地库句子冒充「资料覆盖」。

### S2 越界控制 Boundary / Anti-hallucination（1–5）

- **定义**：是否出现资料与本地 `evidence_used` 均未支撑的 **可核验断言**（销量、人次、排名、假引语、假播放量等）。  
- **5**：无越界；**1**：出现禁止项或明确假数据。  
- **一票**：严重越界时，即使文笔好，**整条不达标**。

### S3 提示硬约束遵从 Hard Prompt Compliance（1–5）

- **定义**：仅评提示中的 **Must / Must-not / 安全 / 格式硬约束**（必须用资料、禁嘲讽受众、要 evidence_notes、禁假统计等）。  
- **不含**：语气美不美、钩子炫不炫（归插件或人工）。  
- 与旧「提示遵从 P1–P5」关系：旧 P4 + 部分 P1 硬槽位 → **S3**；旧 P2/P3 软偏好 → 插件或人工。

### S4 可追溯性 Traceability（1–5）

- **定义**：`evidence_notes` 能否映射到 Evidence#；有用户资料时 `source_type` 可区分用户上传/本地库。  
- **5**：notes 具体且双源可辨；**1**：成稿有专名数字但 notes 空或假编号。

### S5 体裁—证据一致 Genre-Evidence Fit（1–5）

- **定义**：成稿是否像在用 **当前体裁合法方式** 组织证据（不是把通稿当 IG 短帖硬塞，也不是帖文写电头长通讯）。粗粒度；细粒度串味见 N3。  
- **无资料**：仍可打（只看形态是否像申报体裁）。

### S6 无资料增益 Ablation Gain（1–5）

- **定义**：同一提示下去掉用户资料后，**专有锚点命中数明显下降**。  
- **达标哲学（保留）**：有料版锚点 ≫ 无料版。  
- **5**：有料≥2 且无料≤有料−2（或无料为 0）；**2**：两边命中一样；**1**：有料也无锚点。  
- **未设计对照的题**：N/A，不拖平均。  
- **设计强制**：对照题的锚点列表必须通过 §3 S1 锚点规范审核。

## 4. 帖文插件 P1–P3（Lasswell + 既有贴文原则）

> 回答「直接评价生成内容」里 **贴文专属** 部分。

### P1 5W 可执行度（1–5）

- Who / Says What / Channel / To Whom / Effect **字段实质非空壳**，且与正文一致（旧 quality「Q-5W」）。  
- Says What = **一个**具体故事点。

### P2 受众桥梁 To Whom（1–5）

- 正文能看出为何 **该国/该受众** 会停；删国名后不能完全变成全球万能稿（旧 Q-audience）。

### P3 渠道短形态 Channel Fit（1–5）

- 长度相对 max_words、平台习惯（X 更短、少长通讯）；钩子服务分享而非通稿收束。

**旧表映射**：`skill_eval_v0.3.2_quality` 的 5W/受众/权威 → **P1+P2** + 权威部分并入 **S2/S4**（权威「进正文」的事实性归共享，不再单独无限加维）。

---

## 5. 通稿插件 N1–N3（语料口径 + 反串味）

### N1 讲述节拍 Narrative Beats（1–5）

- 导语（反差/定义）→ 场景/人物 → 机制 → 数据（有则）→ 意义收束；允许合并，不可只有口号。

### N2 强调面与口径 Emphasis & Lexicon（1–5）

- 在证据支持下点到生态/能源/民生（或人文类：技能/交流）中合理组合；优先 clean energy / win-win / livelihood 等语料词；禁 GenZ 词作主风格。

### N3 与帖文隔离 Anti-cross-contamination（1–5）

- 无 Imagine / Would you visit / emoji 堆砌 / 博主人设第一人称种草；genre 与 skill 注入正确。

**旧表映射**：`skill_eval_v0.4_news` 六维 → N1≈讲述，N2≈强调+口径，N3≈隔离；语气/证据 → **S 层**。

## 6. 旧「提示遵从」拆分（避免重复计分）

| 旧 materials_flex 提示遵从子维 | 新归宿 |
|--------------------------------|--------|
| P1 意图槽位（国/平台/字数） | 硬槽 → **S3**；软表达 → **P2/P3 或 N*** |
| P2 语气 | **人工档**（推荐）或帖文 P 轻量机打 |
| P3 讲述/单点/引语/列表 | **资料关联的用料指令** → 并入 **S1 检查方式** + 专表字段 `narrative_directive`；成稿「好不好讲」→ **P1/N1** |
| P4 硬约束 | **S3** |
| P5 用料指令 | **S1/S6**（是否按指令用上专有事实） |

旧六维「提示遵从」**不再作为与 S1–S6 并列的独立总分维**，以免和覆盖/越界双扣。

## 8. 相对旧体系的差距（改动了什么 / 为什么）

| 维度 | 原来 | 现在 v1 | 差距说明 |
|------|------|---------|----------|
| 结构 | 三套表分叉，分数不可比 | **一张卡：共享+插件** | 消除「贴文 29 vs 通稿 27」假对比 |
| 资料作用 | 仅 flex 表强调 | **S1/S2/S4/S6 升为共享** | 上传资料变成主能力指标，而非附加题 |
| 提示遵从 | 一个大维揉风格+硬约束+用料 | **硬→S3，用料→S1/S6，软→插件/人工** | 减少重复扣分、职责清晰 |
| 5W | 只在贴文 quality | **仅帖文插件 P1** | 通稿不再硬套 5W |
| 通稿专属 | 六维独立 | **压缩为 N1–N3** | 证据/越界与贴文共用 S，避免双标 |
| 锚点/增益 | 未强制专有 | **锚点规范 + MF03 教训写入** | 降低假失败/假成功 |
| 权威维 | quality 单独 Q-authority | **并入 S2/S4** | 少一个易与越界重叠的维 |
| 科学性 | 纯机打启发式 | **机打层 + 预留人工层 + 分列报告** | 向可验证量表靠近，仍非心理测量学终极版 |
| 总分 | 各表自说自话 /30 | **Shared/30 + Plugin/15 分列**；可选总分 = Shared + Plugin（满分 45） | 汇报必须写两截 |

**刻意没有改的（继承）**

- 证据硬边界、不嘲讽受众、门控拒编跑题；  
- 「无资料后专有锚点应明显下降」作为 S6 达标哲学；  
- 帖文先 5W、通稿反 GenZ 串味的产品立场。

## 9. 更科学一档的落地约定（供后续人工验证）

1. **双轨**：每条机打 S1/S2/S4/S6（及可规则化的 S3）；**人工**抽检 P2、N1、语气、讲述焦点（每轮≥20% 样本或失败全检）。  
2. **报告**：同时给机打均分、人工均分、二者相关（Spearman）；不单报神话总分。  
3. **锚点评审**：新题入库前两人过目锚点是否「theme-不可得」。  
4. **分层**：短令 / 长 Brief / 干扰指令 / 薄资料 / 列表资料 / 门控，分层报达标率。  
5. **Changelog**：改 skill 只针对某一 S 或插件维，避免一次改光。  

**可选加权（答辩用，须声明）**  
`Total45 = Shared + Plugin`；有资料题强调资料时可用  
`Total = 0.7×(Shared/30)×30 + 0.3×(Plugin/15)×15` 的变形——**默认不采用**，优先分列。
