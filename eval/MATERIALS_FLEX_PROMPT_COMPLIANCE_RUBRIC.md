# 用户资料灵活化评测 ·「提示遵从」评价标准（完整版）

> 对应产品逻辑：上传资料后，成稿须**正确用事实**，并按用户提示词**化用语气/讲述/约束**；与「无资料自由发挥」可区分。  
> 本维是六维之一；与「资料覆盖」「越界控制」分工：**覆盖=用了哪些事实；越界=有没有编；提示遵从=有没有按用户的“怎么写”来写。**

---

## 0. 定义与边界

**提示遵从（Prompt Compliance）**：在**不违背证据硬边界**的前提下，成稿对用户提示词中可解析意图的满足程度。

| 冲突时的优先级（硬性） | 说明 |
|------------------------|------|
| 1. 证据事实 | 资料/本地库未写的数字、引语、专名**宁可不写**，不可为“更听话”而编造 |
| 2. 用户硬约束 | 「必须用资料」「不要编互动数据」「禁止嘲讽受众」等 |
| 3. 用户软偏好 | 语气、讲述角度、字数、emoji、轻松/克制 |
| 4. 系统默认 | identity/tone/platform 缺省值 |

**不得**把「提示遵从」理解成：用户说什么风格就牺牲事实。正确理解是：**事实锚定资料，表达跟随提示。**

---

## 1. 子维度（建议加权合成 1–5 分）

### P1 意图槽位落地（Intent slots）· 权重 20%
用户提示里出现的槽位，成稿/5W 须一致：

| 槽位 | 检验 |
|------|------|
| 受众国/对象 | `to_whom` 与正文桥梁一致 |
| 平台 | 长度、标签习惯、是否口播感 |
| 字数 | 相对 `max_words` 合理（±35% 内，薄资料允许更短） |
| 语言 | 正文语言与要求一致 |
| 人设/语气词 | Who 口吻与 tone 不明显打架 |

**扣分**：填了 America 却写成纯英国茶桌且无美国钩子；要 Twitter 却写成长通讯。

### P2 语气与情感色彩（Tone）· 权重 15%
| 用户要求 | 合格 | 不合格 |
|----------|------|--------|
| optimistic / 轻松 | 正向、可分享，不冷冰冰公文 | 通稿腔堆砌口号 |
| serious | 克制、少 emoji | 玩梗、嘲讽 |
| humorous | 轻巧幽默 | 贬低受众/他国 |
| 明确「不要空洞口号」 | 场景句为主 | 「美丽多元」空转 |

### P3 讲述方式 / 叙事框架（Narrative framing）· 权重 25%（核心）
这是「化用资料」的关键：同一资料，不同讲法。

| 提示信号 | 期望讲述 | 检验点 |
|----------|----------|--------|
| 生活化 / 日记 / 采青 | 第一现场、时间动作链 | 出现资料中的动作/时间锚 |
| 只突出某一细节 | 正文焦点收敛到该细节 | 不平均罗列全部资料 |
| 保留某人原话/引语 | 引语进正文或明确转述 | 不改成无关金句 |
| 第三方/YouTuber 镜头 | 观察者视角 | 不写成政府公报 |
| 列表展台事实 | 覆盖≥2 条列表项 | 只写氛围不写展台 |
| 先 5W 再正文 | five_w 非空壳且与正文一致 | 只有正文无策划 |

**扣分**：提示要「只写焊接火花」，却写成体验团政策长介绍且无火花。

### P4 硬约束遵从（Hard constraints）· 权重 25%
| 类型 | 例 | 违约即重扣 |
|------|-----|------------|
| Must-use | 必须使用粘贴资料 | 正文零用户锚点 |
| Must-not | 不要编互动数据/销量 | 出现播放量、满意度% |
| Safety | 不嘲讽圣诞/受众 | 出现攻击句 |
| Format | 要 evidence_notes / 区分来源 | notes 全空或无法映射 |
| Genre | 明确要帖文则勿通稿腔 | 电头+长通讯当 IG 帖 |

### P5 资料使用指令（Material-use directives）· 权重 15%
提示词对**如何用资料**的显式要求：

| 指令类型 | 合格 |
|----------|------|
| 优先用户资料 | 用户锚点密度 ≥ 本地库空话 |
| 本地库仅权威背书 | UNESCO/机构名在 notes，不抢戏 |
| 「不要额外发挥」 | 无资料外情节 |
| 多段资料 | 至少用到 2 段中的关键信息（若提示要求） |

## 2. 合成分数（1–5）操作定义

| 分 | 含义 |
|----|------|
| 5 | P1–P5 无明显违约；讲述框架与提示匹配；事实未为风格让路 |
| 4 | 槽位与硬约束达标；讲述略散或语气差一点 |
| 3 | 大致像在回应用户，但焦点偏移或软偏好未落实 |
| 2 | 多项槽位/硬约束落空；或为风格编造边缘细节 |
| 1 | 忽略提示或严重串味（如要帖文却 GenZ 胡编 / 要资料却零锚点） |

**一票否决（本维最高 2 分）**：为遵从风格而写出资料没有的可核验事实；或 Must-use 资料却 0 锚点。

---

## 3. 与其他五维的关系（防重复计分）

| 维 | 管什么 | 不管什么 |
|----|--------|----------|
| 资料覆盖 | 锚点命中数量/比例 | 讲得好不好 |
| 越界控制 | 有没有编 | 有没有按语气写 |
| **提示遵从** | **怎么写、写什么焦点** | 锚点个数本身（交给覆盖） |
| 平台适配 | 平台形式惯例 | 受众国桥梁（可与 P1 重叠，平台维侧重长度/标签/视觉词） |
| 双源可追溯 | source_type / notes 映射 | 文笔 |
| 相对无资料增益 | 有料版锚点 ≫ 无料版 | 文笔绝对分 |

---

## 4. 评测时提示词里建议标注的字段（写入 CSV）

- `prompt_slots`：country/platform/words/tone/lang  
- `narrative_directive`：生活化|单点聚焦|引语优先|列表覆盖|第三方视角|5W策划…  
- `hard_constraints`：must_use_materials|no_fake_stats|no_audience_mock|…  
- `material_use_directive`：user_first|authority_backup_only|no_extra_plot|…

打分脚本按这些字段自动检查 + 人工抽检讲述焦点。
