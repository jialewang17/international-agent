# 用户草稿评价表 · 权重换算与双轨维度库（v0）

**用途**：把会议向「评价标准」草稿（一级/二级排序）换算为可答辩权重；并单独建立「用户材料运用」评价轨。  
**不替代**：`UNIFIED_SCORECARD_v1.md`（工程打分仍以之为准）。  
**约定**：括号内数字 = **排序（1=最重要）**，不是权重。

---

## 1. 定权方法

采用层级 **ROC（Rank Order Centroid）**：

\[
w_k=\frac{1}{n}\sum_{i=k}^{n}\frac{1}{i}\quad(k=1\text{ 最重要})
\]

全局权重 = 一级 ROC × 组内二级 ROC。  
（附录给线性秩权重作敏感对照；答辩建议主报 ROC。）

一级 ROC：内容 **0.5208** ＞ 用户偏好 **0.2708** ＞ 信息来源 **0.1458** ＞ 社媒环境 **0.0625**。

礼貌性在社媒类仅 1 项，组内权重 = 1。

## 3. 对你这张表的评价（优点 / 风险 / 建议）

### 3.1 优点

| 点 | 说明 |
|----|------|
| 结构对齐文献 | 四类一级贴近李蕾 AUGC（内容/来源/偏好/社媒），便于写「有出处」 |
| 会议五维基本落位 | 权威、证据、本地化、钩子/参与、自然度均有二级 |
| 内容优先正确 | 准确性组内第 1、内容类一级第 1，与郭文「内容最重」、工程 S2 精神一致 |
| 社媒礼貌独立 | 礼貌性可作「冒犯一票否决」门控，不必靠高权重撑场面 |

### 3.2 主要风险

| 问题 | 表现 | 建议 |
|------|------|------|
| **解释与维度名错位** | 「信源权威度」解释写成「信息可获取」→ 这是李蕾的**可访问性**，不是权威 | 权威：官方/权威媒体/可核验来源层级；可获取另开或并入追溯 |
| **事例性 ↔ 证据支撑重叠** | 二者都像「有没有论据」 | 事例性=叙事具象/场景句；证据支撑=可核验断言有 evidence 映射（对齐 S2/S4） |
| **自然度全局仅 ~1.7%** | 会议核心「意图不生硬」权重过低 | 若坚持排序，答辩易被问；建议把自然度至少调到偏好组内第 2，或与礼貌同为**硬门控**（不合格直接不达标） |
| **参与感 vs 有趣性** | 钩子与趣味难区分，易双扣 | 有趣=愿读；参与=可互动动作（问句/同款/挑战）；打分规则写清 |
| **缺少「可追溯」** | AIGC 特有维（郭/王）未进表 | 有资料场景用材料轨 S4；无资料也建议保留 notes/来源标注 |
| **缺少呈现清晰（演示性）** | 李蕾权重最高维未进 | 帖文可并入「事例性」操作定义，或加「呈现清晰」辅维 |
| **礼貌性权低但风险高** | 6% 挡不住严重冒犯样本「总分仍过线」 | **一票否决**：出现冒犯→礼貌=0 且整卷不达标 |

## 4. 材料运用轨：为何必须「另开一轨」

你的表评的是：**生成内容是否像「合格的国际传播成稿」**（受众向质量）。  
你补充的问题评的是：**有上传资料时，模型是否把料用对、用足、用得像用户要的样子**（任务向 grounding）。

两轨正交：可以「写得很本地化但没用资料」或「锚点堆满但口号生硬」。工程上已是 Shared S1/S2/S4/S6 思路；答辩也建议 **双轨报分，不混进上面 10 维总分**（无资料时材料轨记 N/A）。

对你那句「借助材料模仿生成用户不满意的文本」——按产品语境理解为：  
**能否用材料生成用户满意稿；若用户不满意，能否按反馈+材料改到满意**（grounded revision），而不是去生成差稿。

## 5. 材料运用 · 文献/框架维度池（大量收集 → 表格）

### 5.1 信息质量与「适合使用」

| 来源 | 可借用维度 | 材料场景含义 |
|------|------------|--------------|
| Eppler & Wittig, fit for use | 场景依赖标准 | 有料/无料达标线不同 |
| Wand & Wang / AIMQ | 正确、完整、一致 | 相对**用户资料**的正确与完整 |
| Wang & Strong 内在/情境/表征 | 相关性、适量、易理解 | 用料是否切题、过量堆砌 |
| 李坤 档案摘要 | 查准/查全；形似神离 | 覆盖率 vs 事实精度分开 |
| 郭亚军 AIGC | 可追溯、可塑性 | 来源可追；同一料可按提示改写 |
| 王佳淇 | 相关性、上下文理解 | 提示+资料联合理解 |
| T/SDAAI 0001-2023 | 主题准确 | 成稿主题不偏离资料主题 |

### 5.2 NLP / 生成评测（可操作化）

| 框架 | 指标要点 | 用法 |
|------|----------|------|
| FActScore | 原子事实被指定知识源支撑的比例 | 用户资料=唯一知识源时的支撑率 |
| Attribution / AIS 类 | 句级是否可归因到源文档 | 对齐 evidence_notes |
| Faithfulness（摘要） | 生成不引入源外事实 | ≈ 越界控制 |
| Coverage / Completeness | 源中关键信息是否出现 | ≈ 资料覆盖 |
| ROUGE/BERTScore | 与参考稿重合 | **仅当**有用户金标准改写稿；日常慎用 |
| G-Eval grounded | 相对源文档的一致/相关 | LLM-as-judge 辅评 |
| RAGAS（RAG 评测族） | faithfulness, answer_relevancy, context_precision/recall | 上传资料≈检索上下文时的类比 |
| Attributed QA / Q² | 答案是否被证据支持 | 通稿引语/数据句 |

### 5.6 「用户满意」怎么测（避免主观空转）

| 测法 | 做法 | 注意 |
|------|------|------|
| 任务完成判定 | 预写 expect + 锚点清单，机打 S1/S2 | 主客观结合 |
| 对照消融 | 同提示有料/无料 | 证伪「假装用料」 |
| 修订轮 | 人工标「不满意原因」→ 再生成 → 看是否消除且不越界 | 对应「改到满意」 |
| 小样本偏好 | 2–3 名同学对「是否像我要的稿」李克特 | 只报材料轨，不替代事实维 |
