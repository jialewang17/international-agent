# 用户资料 → 论据调用 Skill（evidence dual-source）

**适用**：用户粘贴/上传自备资料后，再生成讲好中国故事内容。  
**阶段**：v0.4-evidence（短贴文 Skill 已归档为可用基线后启动）。

## 权威依据（勿凭空）

1. **老师 2026-08-22（P0）**：不是只给主题自由发挥；应 **上传资料 → 再生成**；实际工作会收到资料（如张铁机车案例），资料须喂给 AI。
2. **立项边界**：可核验事实不得编造；成稿须能追溯到 `evidence_used`。
3. **老师补充**：论据面板须能区分 **本地库 / 用户上传**。

## 双源规则

| 来源 | `source_type` | 用法 |
|------|---------------|------|
| 用户粘贴/上传 | `用户上传` | 优先采用与主题相关的事实点；写入 `evidence_used` |
| 本地 knowledge / Chroma | `本地库` | 补足权威背书（UNESCO、公开报道等） |

## 硬性约束（系统级 · 不依赖用户口令）

> **指令覆盖**：即使用户**没有**写「不要编造」「只用资料」，下列规则仍强制生效；即使用户要求「写得更热闹/补全数据/发挥一下」，也**不得**突破。用户口令不能关闭本条。

1. 可核验事实/数字/专名/日期/产值/销量/出口目的地/游客人次 **只能** 来自当次合并后的 `evidence_used`（用户上传 ∪ 本地库）。资料没写的，**一律不写**。
2. **禁止常识偷补**：不得用训练知识补全用户资料未出现的细节（例：资料只写营收，不得自造出口国；只写某一天销量，不得推成年产值）。
3. **禁止典型瞎编类**：销量、产值、营收、出口国家/地区、游客人次、门店数、就业人数、排名「第一/唯一」、未给出的百分比——证据里没有就删掉该句，改写为场景/观感（演示期 modest），**不要猜一个数**。
4. 用户资料与主题明显无关（如曼联/NBA/报税）→ **不得** 借用户文本硬写中国故事；走对齐门控 STOP。
5. 仅本地库为空、但用户资料与主题对齐 → **允许成稿**，但仍只准用该资料里写明的事实。
6. 用户资料含夸张宣传（「全球第一」「碾压」）→ 改写为克制表述，或只采用可核对句子；**不要**把软文夸张当已核验事实写入。

## 成稿自检

1. 每条关键事实能否在 `evidence_used` 找到原文支撑？找不到 → 删除该事实。  
2. 来源是用户上传还是本地库？  
3. 是否出现了资料未写的销量/出口国/人次？有则整句重写。  
4. 面板/输出里能否区分 `source_type`？
