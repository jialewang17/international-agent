# 体裁方法：indepth（深度报道 / 解释性 / 调查性 / 专题）

> 来源：原 `genres/indepth/china-story-indepth.md`（v1）+ `genres/indepth/china-story-indepth-reference.md`
> 层级变更：由「独立顶层 Skill」降为 Generation Skill 的内部方法（来源：审查报告 §六）
> **这是本轮从 feature 中分离出来的新体裁**（来源：审查报告 §一：「最新版已经把 feature 和 indepth 分开，现在是六类体裁，不再是旧版本的五类」）

## 何时使用

用于深度报道、解释性报道、调查性报道、专题、政策/产业/社会机制说明。回答"**为什么发生、怎么运转、谁受影响、证据边界是什么**"。不以文学场景或口号作为主要推进力。

**与 feature 的分界**：`feature` 回答"这件事是什么样"（场景/人物/体验）；`indepth` 回答"为什么、怎么运转"（机制/数据/多来源）。

---

## 1. 核心问题门控

把请求收敛为一个可由材料回答的 `core_question`。例如：

- 不写"介绍某湿地保护"；
- 改为"这片湿地的巡护数据如何产生、如何被使用，现有材料能证明到哪一步？"

若核心问题无法由现有材料回答，**先输出 `research_gaps` 和需要补充的资料，不得写成完整报道**。

---

## 2. 研究问题清单

列出 **3–6 个互不重复**的 `research_questions`，按需覆盖：

1. **现象/范围**：发生了什么，范围多大？
2. **机制**：流程、资源、政策或技术如何运转？
3. **参与者**：谁执行、谁受影响、谁提出异议？
4. **依据**：哪些数字、文件、原话或观察支持判断？
5. **边界**：哪些时间、地点、样本或因果尚未证明？

```yaml
research_questions:
  - id: RQ1
    question: "这个现象在什么范围和时间内成立？"
    status: answered        # answered | partial | unanswered | conflict
    evidence_ids: [U1, K2]
    gap_note: ""
```

未回答的问题**必须进入 `research_gaps[]`**，正文对应处写出边界，**不用常识补齐**。

### 证据成熟度

| 状态 | 含义 | 正文动作 |
|---|---|---|
| `answered` | 证据足以在限定范围内回答 | 正常写，保留口径 |
| `partial` | 只支持一部分或范围较窄 | 收缩主语/时间/确定性 |
| `unanswered` | 无证据 | 列 `research_gaps`，不硬写 |
| `conflict` | 来源互相矛盾 | 并列说明或 `needs_human` |

---

## 3. 证据与研究

按 `references/output-contracts.md` 使用 `EvidencePack`（`U/K/W` 编号）；按 `evidence_map[]` 建立论断映射。

> **[D-01] 深度报道不自动等于"联网搜索"**
> 来源：原 `genres/indepth/china-story-indepth.md` §3。
> 依据：证据由 Ground 阶段建立。若运行时没有搜索工具，**不能声称已完成外部研究**，只能使用 `U`（用户材料）与 `K`（本地库），并把缺口写入 `research_gaps`。

**以下情形建议至少两条相互独立来源，或标 `needs_human`**：

- 争议性事实、归责、因果、排名；
- 会随时间变化的政策、价格、人数、规模；
- 代表"公众/行业/海外受众"的概括；
- 只有单一宣传来源支持的重大结论。

---

## 4. 解释结构

```text
lede       核心事实 + 核心问题 + 范围/时点
sections[] 每节只回答一个研究子问题
  - 现象与范围
  - 机制与执行链条
  - 参与者与不同视角（有材料才写）
  - 数据/文件/原话（带来源和口径）
boundary   未查到、证据冲突、不能推出的结论
close      回答核心问题，但不把未知写成已解决
```

小标题用**回答性陈述句**，例如"巡护数据先由现场记录产生，再进入月度汇总"，而不是空泛的"背景""意义"。

每节正文至少挂一个 `evidence_id`；**没有证据的段落只能是明确标注的分析框架，不能伪装成事实**。

### 解释层级

1. **观察**：来源直接报告了什么；
2. **机制**：来源明确解释了怎样运转；
3. **有限推断**：由多个证据共同支持，但仍需用"可能/显示/在本案例中"；
4. **外推**：超出样本或时间范围，**默认禁止**，除非有独立证据。

---

## 5. 数据与因果规则

- 数据写全**单位、时间、样本/统计范围和来源**；口径缺失就不精确化。
- "相关""同时发生""项目方声称"**不能**改写成"导致""证明有效"。
- 单点、单日、单站、单个受访者**不能**推全年、全域、全行业或公众共识。
- 解释机制时区分：来源明确说明的机制 / 基于材料的有限推断 / 尚未验证的假设。

---

## 6. 写作与语气

第三人称、清晰、克制。**允许有一处具体场景**帮助读者进入，但不能让场景取代研究。

禁止：emoji、营销 CTA、Imagine 式开场、对他国的贬损、无依据的"普遍/必然/第一"。

---

## 输出协议

```yaml
genre: indepth
format: in_depth_report
genre_status: methods_in
headline: ""
dek: ""
core_question: ""
lede: ""
research_questions: []
sections: []
boundary: []
close: ""
evidence_used: []
evidence_map: []
research_gaps: []
needs_human: []
```

- `research_questions[]` 至少含 `question`、`status`、`evidence_ids`、`gap_note`
- `sections[]` 至少含 `heading`、`body`、`evidence_ids`

### 边界段模板

```text
本稿能确认的是……
现有材料不能确认……
一份来源提出……，但尚未有独立材料验证……
因此，本文不把……写成……
```

### 适合使用外部检索的情况

仅当系统提供检索工具且能保存来源快照/URL、发布日期和定位时使用。检索结果用于补充研究，**不会自动覆盖用户材料**；与用户材料冲突时保留冲突并交人工。

---

## 红线

不把"资料很多"当作研究完成；不把引用链接当作已验证支持；不省略未回答问题；不以"结论先行"掩盖证据不足；**不更新知识库**。
