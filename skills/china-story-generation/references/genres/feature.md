# 体裁方法：feature（特稿 / 非虚构长文 / longform）

> 来源：原 `genres/feature/china-story-feature.md`（v3）+ `genres/feature/china-story-feature-reference.md`
> 层级变更：由「独立顶层 Skill」降为 Generation Skill 的内部方法（来源：审查报告 §六）

## 何时使用

用于特稿、非虚构长文、长篇特写、人物/地方/文化/科技故事。以现场和细节组织阅读体验，但**不虚构现场**。回答"这件事是什么样"，不是"把所有背景都讲完"。

**不要用于**：解释性/调查性议题（`indepth`）、短消息/通稿（`news`）、分镜（`script`）、误解清单（`faq`）。

---

## 0. 素材充分性门控

先数独立事实锚点，并检查**三类最低材料**：

1. 至少一个可还原的场景、动作或物件；
2. 至少一个变化、选择、张力或正在发生的过程；
3. 至少一个可回扣的意义线索、人物处境或具体结果。

锚点数量只用于**建议篇幅**，不是机械硬阈值。下表以英文词数为参考；中文或其他语言按信息密度等比例换算，**不能为了凑词数扩写**：

| 锚点 | 建议篇幅 | 处理 |
|---:|---:|---|
| 1–4 | 300–600 词 | 写短特写/场景稿；不要冒充完整长文 |
| 5–7 | 600–1000 词 | 短特稿 |
| 8–14 | 1000–1800 词 | 标准特稿 |
| ≥15 | 1800–3000 词 | 完整长文；仍以材料为上限 |

若三类最低材料缺一，**停止写长文**，输出 `missing_fields` 和补料问题；用户只要短帖时，可降级为 `post`，但必须说明体裁变化。

输出 `material_budget`：`anchor_count`、`anchor_examples`、`recommended_words`、`chosen_words`、`gate_decision`。

> **[F-01] 素材闸门由机械硬阈值改为「三类最低材料 + 建议篇幅」**
> 来源：`ChinaStory-final-skills` 内部 v2 → v3 的修订；审查报告 §一 确认「最新版已经把 feature 和 indepth 分开」且保留「素材篇幅匹配方法」。
> 依据：旧草案「锚点 < 5 一律停笔」会误杀 1–4 个锚点但材料完整的短稿；改为三类材料是否齐全决定能否写长文，锚点数只决定篇幅上限。

## 1. 写前五问

内部回答：

- 为什么值得写？为什么是现在（若材料支持）？
- 故事的时代、期限、地点、冲突、人性五维度分别是什么？未知就写 `unknown`。
- 一句话主心骨是什么？
- 读者首先能看到、听到或触到什么？
- 现有材料更适合哪种结构，为什么？

**没有人物材料时，不要声称"个体视角"；没有冲突材料时，不制造戏剧冲突。**

### 五维度工作表

| 维度 | 必须记录 | 缺失时 |
|---|---|---|
| 时代 | 发生在哪个历史/当下阶段 | 不写宏大年代判断 |
| 期限 | 一次事件、一个季节或更长过程 | 用"目前/在这次工程中"，不自造年限 |
| 地点 | 材料给出的空间 | 不补城市、机构或地标 |
| 冲突 | 已发生的选择、限制或变化 | 不发明对立双方 |
| 人性 | 有材料支持的处境、关系或选择 | 无人物材料则留空 |

## 2. 结构判断

读取 `knowledge/storytelling_framework.txt` 或其项目摘要，输出四选一：

- `高度适配`：库中规律可直接使用；
- `部分适配`：说明保留和舍弃的模块；
- `组合`：说明不同模块的自然衔接；
- `不适配`：按材料临时组织，并标注"临时方案，非库内验证结构"。

**框架是选择工具，不是固定模板。不得为了凑 A–H 模块添加事实或人物。**

### 结构备选

1. 场景 → 变化 → 回扣；
2. 一个物件/动作贯穿多节；
3. 时间线（仅当时间节点有证据）；
4. 多线并行（每条线都有独立证据）；
5. 环状结构（结尾回到开头，但不得重复全文）。

---

## 3. 写作骨架

优先采用：具体开场 → 选择/变化/冲突 → 细节推进 → 回到主心骨的克制收束。可以按时间、空间、多线或环状组织，但**每节都要有材料功能**。

- 开头前三段给出可信的具体场景或未解问题，不用口号。
- 每段只推进一个事实、动作或观察；重复同一论点应删除。
- 细节要可还原，**五感只能来自材料**。
- 意义句必须建立在前文事实之上；不要把宣传判断写成事实。
- 结尾从场景、悬空、克制回扣、首尾循环、隐喻或反转中择一，且材料须支持。

### 细节选择

优先选择同时满足"可还原、与变化有关、能区别于空泛形容词、来源可定位"的细节。**一个准确细节胜过一串未经材料支持的五感描写。**

---

## 4. 逐句证据绑定

读取 `references/output-contracts.md` 的 `evidence_map[]` 字段表。事实、数字、专名、引语、现场细节和因果句逐条登记；挂不上就删除或改为明确的解释性判断。`pull_quote` 只能来自材料原话，**无原话就留空**。

---

## 5. 成稿前闸门

- **具体性**：任意连续两段不能都只有概括、评价或意义；至少有一段可见/可听/可触的事实细节或证据。
- **人物真实性**：没有人物材料就不写姓名、心理、对话、身份、日程或"工程师们正在想……"等个体化内容。
- **抽象比例**：意义/价值判断服务于故事，不成为每段结尾的套话；全文顶部意义句建议不超过 2–3 处。
- **引语**：原文逐字可定位；译文单列翻译说明。
- **语种**：正文单语种；专名按受众需要保留原文并给解释。
- **篇幅**：不超过 `material_budget` 建议区间；超出必须列出新增证据和理由。

## 输出协议

必须输出：

```yaml
genre: feature
format: longform
genre_status: methods_in
headline: ""
dek: ""
one_liner: ""
five_dimensions:
  era: ""
  time_span: ""
  place: ""
  conflict: ""
  human_dimension: ""
material_budget: {}
structure_decision: {}
body: ""
evidence_used: []
evidence_map: []
```

可选：`pull_quote`、`suggested_visuals`、`fact_gaps`、`missing_fields`、`needs_human`。

**不要输出**：帖文 `five_w`、hashtags 堆、emoji、营销 CTA、未经证据支持的宏大结论。

## 常见失败与修复

| 失败 | 修复 |
|---|---|
| 4 条素材写成 2000 词 | 缩短、转短特稿或追问素材 |
| 无人物却写"工程师认为" | 改成"材料显示/项目采取了……" |
| 自己写一句再标为 pull quote | 删除或回到原材料找原话 |
| 背景常识段落很流畅 | 删除；若必须保留，补来源和范围 |
| 结尾再次总结全文 | 用最后一个有证据的场景或克制回扣 |

## 红线

宁短勿编；不抄教材范文；不把知识库中的通用背景自动写入正文；**不把"写得像特稿"当作事实核验**。
