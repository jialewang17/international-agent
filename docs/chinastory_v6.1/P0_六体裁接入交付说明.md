## 二、修改前后行为对照

| 场景 | 修改前 | 修改后 |
|---|---|---|
| 用户显式选 `feature`/`indepth`/`script`/`faq` | 只能走 post，五体裁共用 Post 模板或被静默转成 Post | 路由到对应体裁卡，注入且仅注入该体裁方法卡，走独立模板；输出按该体裁契约解析 |
| 非法 Genre（如 `genre=story`） | 静默按 post 处理 | `INVALID_GENRE`，明确报错，不调用模型 |
| Genre 与 Format 冲突（如 `news` + `social_post`） | 静默忽略 Format | `GENRE_FORMAT_CONFLICT`，要求重新选择 |
| 尚未实现输出结构的格式（如 `post` + `thread`） | 伪装成功，返回单个 `post` 字符串 | `UNSUPPORTED_GENERATION`，明确未支持 |
| Skill 文件缺失/为空/禁用/超预算 | 静默继续，`(no skill loaded)` 也能"成功"出稿 | `SKILL_LOAD_FAILED`，返回明细，不调用模型，`loaded_method_id` 不允许用期望值冒充 |
| 模型输出非法 JSON | 把原始文本塞进 `post` 字段当合格成稿 | `OUTPUT_INVALID` + `parse_warning`，不伪装成功 |
| Prompt 注入证据 | 无记录，无法审计"预期加载"与"实际加载" | `skill_load` 诊断块：requested_method_id / loaded_method_id / loaded_files / load_status / error_reason / 截断与哈希标识；区分路由成功、加载成功、生成成功三个状态 |
| Post 专属规则泄漏到通稿 | Emoji / 5W Caption / 营销 CTA 规则可能进入 news prompt | news 与 genre 模板完全分离，测试断言不含 Post 专属文案 |

验收要点（详见 `acceptance_report.txt`）：

1. **映射一致性**：skills.yaml 与契约差异 0；六体裁的 skill_id / 方法卡 / 默认 format / 文件存在性全部 OK。
2. **六体裁真实链路**：六个体裁全部路由成功、加载成功、仅注入本体裁卡、注入字符量分别为 post 12912 / news 5934 / feature 3365 / indepth 3157 / script 998 / faq 899，输出字段齐全。
3. **失败路径**：`INVALID_GENRE` / `GENRE_FORMAT_CONFLICT` / `UNSUPPORTED_GENERATION` 三类失败均不调用模型、不产出成稿。
4. **显式选择优先**：`theme 含"深度报道"关键词` 但显式 `genre=post` → post；显式 `genre=indepth` → indepth（来源均为 user_override）。
5. **Prompt 样例**：post 18799 字符、news 11863 字符（脱敏，不含密钥与真实用户数据）。

API 层失败路径（FastAPI TestClient 实测）：

| `{"genre":"story"}` | `ok:false, generation_status=INVALID_GENRE, post=""` |

## 四、尚未支持的体裁 / Format

- `post` 体裁的 `thread` / `visual_story` / `caption_only` 三种 Format：方法卡（post.md v3.2）已定义结构与输出要求，但后端输出结构与前端尚未接线，当前明确返回 `UNSUPPORTED_GENERATION`，**不伪装成功**。
- 除上述外，六体裁的默认 Format 均已支持端到端生成。

## 五、剩余集成风险

1. **未宣称全链路完成**：本次只修复 Skill 到 Create 生成路径的稳定接入；Define → Ground 的证据门禁行为保留原样，`Claim`/`EvidencePack`/`Coverage`/`EvaluationResult` 等核心数据定义未改动。
2. **E2E 文本质量未验证**：当前测试全部用替身模型（不调用真实大模型）；真实模型的成稿质量需在接入有效 API Key 后另行验证。
3. **前端展示兼容**：非 Post 体裁输出的 `headline/article` 等字段与旧前端 `post` 字段的兼容展示待前端确认。
4. **旧工具环**：`tools/load_story_knowledge.py` 等旧工具保留在仓库中供旧链路兼容，v6.1 生成路径已不依赖；后续可评估归档。
