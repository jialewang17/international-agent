# 国际传播 Agent 流程总纲 v1（已锁定）

> 状态：**讨论锁定 · 一期开发中**  
> 锁定日期：2026-09-15  
> 架构选型：**C 混合主动门控（交互脊柱）× B 跨文化证据（内容脊柱）× A Plan→Translate→Review（认知骨架）**  
> 多代理 Critic（原候选 D）：**一期不做**  
> 文献借鉴表：`docs/PIPELINE_LIT_MAP.md`（打包上传用）

---

## 1. 目标

1. 用户提示词（+ 可选资料 + 前端参数）→ **可见路径** → Skill 中间环 → 成稿。  
2. 开发期与用户侧都能看见链路；关键环节可确认/跳过；成稿后可提出修改。  
3. 不同提示词走「共享主干 + 体裁/任务分支」，不另起无关架构。

---

## 2. 理论与实践依据（摘要）

| 来源 | 作用 |
|------|------|
| Flower & Hayes 1981；Gero et al. 2022 | Plan / Translate / Review |
| Horvitz 1999 | 不确定才 Ask；可跳过非硬门 |
| 江盈盈 2024（跨文化人机协同创意写作） | 调研→叙事生成→反馈 |
| Paper Pilot；Verify-RAG；R³ | 证据门、批准门、改稿 Accept/Reject |
| 知网智能写作产品形态 | 参数/大纲确认 → 生成 → 改写润色 |
| 会议 0822 + `FRONTEND_REQUIREMENTS_FROM_MEETING_0822.md` | 主题→资料→口径→初稿→多轮优化；可停顿可全自动；双栏对话为理想态 |

## 3. 主流程图（一期实现必须对齐）

```text
提示词 + 可选资料 + 前端参数（国家/平台/语气/体裁…）
        │
        ▼
   不确定度（高→多问；低→可跳过可选门）
        │
        ▼
 【硬门 G1】主题 / 体裁 / 受众 确认
   （体裁可用下拉；受众国家/平台等用前端选项，避免中途再问一遍）
        │
        ▼
 【可选 G2】Skill 套件展示与确认
   intl_comm + 体裁 skill（± evidence_user_materials）
        │
        ▼
   双源证据汇聚（用户上传 ∪ 本地库）
        │
        ▼
 【硬门 G3】有证据且主题对齐？ ──否──► 停止并说明
        │是
        ▼
 【可选 G4】口径 / 语气 / 框架变量确认
        │
        ▼
   Translate：体裁 Prompt + Skill 约束 → 初稿
   （含 script：直接生成，不因 incomplete 额外前置确认；须标注 genre_status）
        │
        ▼
 【可选/主交互 G6】成稿修改：接受 / 拒绝 / 反馈再生成
        │
        ▼
 【硬门 G7】人工定稿放行
        │
        ▼
 成稿包：正文 + skills_applied + evidence_used + 门决策日志
```

### 硬门 vs 可跳过（已拍板）

| 门 | 类型 | 说明 |
|----|------|------|
| G1 主题/体裁/受众 | **硬门** | 体裁与跨文化参数优先用**前端选项**一次选齐 |
| G3 证据对齐 | **硬门** | 无证据或主题不对齐则停 |
| G7 定稿放行 | **硬门** | 发布/导出前人工放行 |
| G2 Skill 确认 | 可跳过 | 默认展示将用 skill；演示可跳过 |
| G4 口径确认 | 可跳过 | 若前端已填语气/长度/语言，可不再弹窗 |
| G6 改稿 | **保留能力** | 不强迫改；用户随时可提修改再生成 |

演示模式：可一键跳过所有可选门；**不可**跳过 G1/G3/G7。

## 4. 跨文化参数：前端选项（已拍板）

不做「生成中途再采访用户」的单独调研步。改为生成前表单，帮助写好有效提示词并直接进入流水线：

| 前端选项（建议） | 作用 |
|------------------|------|
| 输出体裁 | post / news / feature / script / reply |
| 目标国家/地区 | 本地化与受众 |
| 平台 | IG / X / 官网等 |
| 语气 / 身份 / 语言 / 长度 | 会议已认可的参数区 |
| 可选资料上传/粘贴 | 双源证据 |

这些字段写入请求体，等价于「跨文化调研」结果，**减少 G1/G4 重复追问**。

---

## 5. Skill 在链路中的位置与原因

- **位置**：G1 之后、成稿（Translate）之前。  
- **原因**：Skill = 共享硬约束（`intl_comm`、有资料时 `evidence_user_materials`）+ 体裁叙事插件；须在主题/体裁锁定后注入，才能保证禁令与字段正确。  
- **可见性**：路径条与结果包均展示 `skills_applied`；G2 可让用户覆盖路由（可选）。

## 6. 不同提示词：流程如何变

| 提示词线索 | 路径 | Skill | 流程差异 |
|------------|------|-------|----------|
| 社交帖文 / 默认未写体裁 | 主线 post | `intl_comm` + `china_story_post`（± evidence） | 5W + hashtags/ops；门控同主链 |
| 新闻通稿 / 新华体 | 主线 news | `intl_comm` + `china_story_news`（± evidence） | 换 prompt/字段；禁帖文腔；口径更严 |
| 特稿 / 深度 | 主线 feature | `intl_comm` + `china_story_feature` | 南周方法框架；可选大纲子门 |
| 短视频脚本 | 主线 script（未完善） | `intl_comm` + `china_story_script` | **直接生成**并标 `incomplete`；**不**前置强制确认；保留成稿后修改（G6） |
| 回复评论 | 支线 reply | `intl_comm` + reply 工具链 | ABSA→检索→回复；跳过 5W/通稿骨架 |
| 主题不清 | 前置选题 | 选题工具后再进主线 | 先选题确认，再进入上表主线 |

## 7. 前端可视化怎么做（对应会议，白话）

会议提了**两件事**，不是二选一对立：

1. **工作流步骤条**（约 09–22 分）：定主题 → 资料 → 口径 → 初稿 → 多轮优化；中间可「确认/跳过」，也可全自动。  
2. **静态页 + 旁边对话框**（约 23:00）：左边看成稿/论据，右边用对话改稿、追问。

**一期落地约定：**

- **主可视化 = 步骤条（运行中点亮 G1→G7）**，硬门暂停，可选门可跳过。  
- **改稿入口 = 成稿区反馈框 / 快捷改稿（G6）**；旁路完整对话作为二期增强，不阻塞一期。

（此前说的「步骤条暂停 vs 旁路对话+日志流」= 上面两条；一期以前者为主、后者作改稿补充。）

---

## 8. 「多代理 Critic」是什么（一期不做）

指再开一个（或多个）模型专门打分/挑错/改写，形成 Researcher→Writer→Reviewer 流水线。  
**一期：单模型生成 + 规则门控（证据/对齐）+ 人工 G6/G7。**  
二期若要自动质检，再加 Critic，且不得绕过本总纲硬门。
